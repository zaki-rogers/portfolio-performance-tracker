# Portfolio Performance Tracker
#### Video Demo: <https://youtu.be/RbLDyL2obcs>
#### Description:

##### What it does
This is a portfolio tracker that calculates both the value and return of an investment portfolio over time. When investing across multiple brokerages, it can be difficult to get a single, combined view of how your overall portfolio is actually performing. This program addresses that by letting the user enter any number of holdings, including a ticker symbol, number of shares purchased, and purchase date. It then uses live data from Yahoo Finance, via the `yfinance` library, to produce a graph of portfolio value over time along with the total percentage return.

##### Usage
When the user runs this program, they are first prompted for a "Ticker Symbol", which must exactly match a valid symbol recognised by Yahoo Finance. They are then asked for the "Quantity of Holdings", which must be an integer, and "Date of Purchase", entered in `YYYY-MM-DD` format. These three inputs are the minimum requirement to add a single holding. The user is then asked "Add another holding? (y/n)" and can enter y or n, case-insensitively, to add further holdings or finish. Once all holdings have been entered, typing n exits the input loop. The program then prints the total portfolio return in the terminal and saves a graph of portfolio value over time, generated using `matplotlib`, covering the period from the earliest purchase date to the current date.

##### How it Works
`add_holdings` appends a new holding to a CSV file, given a `filepath`, a ticker, quantity, and purchase date. If the file does not already exist, it first writes a header row (`ticker`, `quantity`, `purchase_date`) before adding the new entry, so the file is created correctly on first use and simply appended to on every run afterward.

`read_holdings` reads all holdings from a CSV file, given a `filepath`, and returns them as a list of dictionaries, where each dictionary represents one holding with `ticker`, `quantity`, and `purchase_date` keys. Unlike `add_holdings`, which writes a single new entry each time it is called, `read_holdings` loops through every row in the file, building up a complete list of every holding ever recorded, so it is called at the start of each run to reconstruct the full portfolio from every previous use of the program.

`fetch_price_history` fetches historical closing price data from Yahoo Finance, given `tickers`, `start`, and `end` dates. If `yfinance` returns no data at all, a `ValueError` is raised. Otherwise, the closing prices are reshaped into a nested dictionary called `price_history`, in the form `{ticker: {date: price}}`, with each date formatted as `YYYY-MM-DD`. This conversion moves the data out of `yfinance`'s pandas-based structure into plain Python dictionaries, so the rest of the program can rely on ordinary loops rather than pandas-specific syntax.

`calculate_daily_values` builds a dictionary called `daily_values`, where each key is a date and each value is the total portfolio value on that day, calculated as the sum of `quantity * price` across every holding. It first uses one ticker from `holdings` to retrieve the full list of dates from `price_history`, since all tickers share the same date range. For each date, it loops through every holding and checks whether that holding's `purchase_date` is on or before the current date, only counting holdings already owned by that point. To handle missing prices caused by different exchanges having different trading calendars, the function carries forward a ticker's last known real price rather than treating a gap as zero value, which previously produced unrealistic sharp drops in the portfolio chart.

`calculate_total_return` uses the `daily_values` dictionary returned by `calculate_daily_values` to compute the portfolio's overall percentage return. The dictionary's keys are extracted and converted into a list called `dates_list`, from which the `earliest_date` and `latest_date` are found by indexing the first and last positions. These dates are then used to look up the corresponding `earliest_value` and `latest_value` from `daily_values`. The total return is calculated using the standard percentage change formula, `(latest_value - earliest_value) / earliest_value * 100`.

`plot_portfolio_value` creates a chart using `matplotlib` to visualise total portfolio value over time. It extracts the keys and values separately from `daily_values`, converting them into two lists called `dates` and `values`. The line chart plots every date against its corresponding value, but the x-axis only labels the first and last dates, keeping the chart readable regardless of how many days of data are plotted. The finished chart is saved to `portfolio_value.png`.

##### Project Structure / Files
This project consists of two Python files. `project.py` contains `main` and the six functions described above. `test_project.py` contains tests for `add_holdings`, `read_holdings`, `fetch_price_history`, `calculate_daily_values`, and `calculate_total_return`, run using `pytest`. `plot_portfolio_value` is not directly tested, since it produces a visual chart rather than a return value that can be asserted against. `requirements.txt` lists the project's dependencies: `yfinance`, `matplotlib`, and `pytest`.

##### Design Decisions
I converted `yfinance`'s pandas-based output into plain Python dictionaries early in `fetch_price_history`, rather than working with pandas objects directly throughout the rest of the program. This let me apply the loop and dictionary skills learned in CS50P, rather than needing to learn pandas syntax at the same time as building the project's core logic.

When holdings belonged to different markets, such as `VUAG.L` on the London Stock Exchange and `NVDA` on the US market, differing trading calendars meant some dates had a real price for one ticker but not the other, producing `NaN` values. Since `NaN` propagates through arithmetic, a single missing price would turn that entire day's total into `NaN`, which in turn caused `calculate_total_return` to output `NaN` whenever it landed on an affected date, and produced unrealistic sharp drops in the portfolio chart. I addressed this by carrying forward each ticker's last known real price on days with missing data, rather than treating the gap as zero value.

I deliberately did not add input validation for malformed dates or non-numeric quantities. I built this primarily as a personal tool to track my own portfolio, so I judged the added complexity wasn't justified given its actual use case.

I chose to store holdings in a CSV file rather than only in memory, so that a holding only needs to be entered once. Each time the program runs, `read_holdings` reconstructs the full portfolio from every entry ever added across previous runs, rather than requiring the user to re-enter every holding each time.

This program currently only supports whole-position purchases and does not account for selling part of a holding. Supporting partial sells would require tracking multiple transactions per ticker rather than a single quantity and purchase date, which I treated as a possible future extension rather than part of this version's scope.

Taken together, these tradeoffs kept the project focused on solving the core problem I set out to solve, rather than expanding its scope beyond what was actually needed.
